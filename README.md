# KoMaP 경진대회 상 분할 모델 (Komap_PhaseSegment)

**2026 KoMaP AI 경진대회 — 고탄성 알루미늄 합금 이미지 상 분할 인공지능 모델 개발**

현미경으로 찍은 알루미늄 합금 사진에서 4가지 성분(Primary Si, $\text{Al}_3\text{Ni}$, Eutectic Si, Al)의 위치를 픽셀 단위로 찾아내는 프로젝트입니다.

처음부터 복잡하고 어려운 기법을 쓰기보다, **데이터를 직접 확인하며 왜 모델이 틀리는지 원인을 찾고, 하나씩 실험해 보며 점수를 올리고, 마지막에 새로운 사진이 들어와도 에러 없이 돌아가도록 코드를 정리한 과정**을 담았습니다.

---

## 1. 프로젝트 한눈에 보기

* **주제**: 알루미늄 합금 현미경 이미지에서 4개 상(Phase) 영역 구분하기
* **데이터**: 총 100장 (학습용 70장 / 검증용 20장 / 제출 평가용 10장)
  * 평가용 10장은 정답 마스크가 제공되지 않아, 검증용 20장으로 성능을 확인했습니다.
* **최종 검증 점수**: 검증 20장 기준 **mIoU 80.0503%** (`0.8005`)
  * 처음 만든 기본 U-Net 모델(`77.1307%`)에서 시작해 단계적으로 `+2.9197%p`를 높였습니다.
* **주요 작업 내용**:
  1. **데이터 점검 및 약점 파악**: 전체 면적의 `6.98%`밖에 안 되고 작게 쪼개져 있는 `Eutectic Si(Eu)`와 그 주변 $\text{Al}_3\text{Ni}$가 서로 헷갈리는 문제를 핵심 과제로 잡았습니다.
  2. **여러 모델의 장점 합치기 (앙상블)**: 전체 형태를 잘 보는 모델(YOLO, DINO)과 각 성분만 따로 찾도록 학습한 모델(U-Net 4개)의 예측 확률을 합쳤습니다.
  3. **경계선 오답 줄이기 및 입력 크기 확대**: 모델이 경계선에서 두 성분을 두고 고민할 때만 살짝 보정해 주고, 가장 찾기 어려운 Eu 모델의 입력 크기를 $640 \times 640$으로 키워 재학습해 최고 점수를 확인했습니다.

## 2. 데이터를 보며 찾은 문제점

코드를 짜기 전에 학습 이미지 70장과 검증 이미지 20장의 크기, 색상, 성분별 비율을 먼저 확인했습니다.

| 번호 | 성분(상) 이름 | 마스크 색상 (RGB) | 학습 데이터 면적 비율 | 데이터를 보며 느낀 특징 |
| :---: | :--- | :---: | :---: | :--- |
| `0` | **Primary Si** | 초록색 `(76, 178, 76)` | `9.43%` | 덩어리가 크고 뚜렷하지만, 아예 없는 사진도 있음 |
| `1` | $\text{Al}_3\text{Ni}$ | 파란색 `(25, 76, 153)` | `26.31%` | 길쭉하고 얇은 형태가 많아 다른 성분과 맞닿는 경계선이 넓음 |
| `2` | **Eutectic Si (Eu)** | 회색 `(204, 204, 204)` | **`6.98%`** | **비율이 가장 적고 잔잔하게 흩어져 있어 모델이 가장 많이 틀림** |
| `3` | **Al (기지상)** | 갈색 `(153, 127, 76)` | `57.28%` | 배경처럼 넓게 깔려 있는 기본 성분 |

### 해결해야 했던 3가지 고민

1. **비율이 너무 적고 작은 Eutectic Si(Eu)**: 바탕이 되는 Al은 절반이 넘는데, Eu는 `6.98%`밖에 되지 않고 작은 점이나 선처럼 흩어져 있었습니다. 그냥 학습시키면 모델이 Eu를 놓치거나 옆에 있는 $\text{Al}_3\text{Ni}$로 잘못 칠하는 경우가 많았습니다.
2. **사진마다 다른 해상도**: $1440 \times 1024$, $1278 \times 909$, $1230 \times 875$, $675 \times 480$ 등 사진 크기가 제각각이었습니다. 사진을 억지로 줄이면 작은 입자가 뭉개지기 때문에, 일정한 크기(타일)로 잘라서 학습하고 추론할 때는 겹치게 이동하며 예측한 뒤 합치는 방식을 썼습니다.
3. **특정 성분이 아예 없는 사진**: 학습용 `A57_step1_sample3`과 검증용 `A71_step2_sample1` 사진에는 정답에 Primary Si가 아예 없었습니다. 정답과 예측 모두에 없는 성분을 평균 계산에서 빼는지(`mIoU_ignore`), 0점으로 넣는지(`mIoU_zero`)에 따라 점수가 달라지기 때문에 두 기준을 모두 확인하며 실험을 관리했습니다.

## 3. 문제를 해결해 나간 과정

유명한 모델을 무작정 가져다 쓰기보다 **문제를 발견하면 가설을 세워 적용해 보고, 실제로 검증 점수가 오르는지 확인**하며 진행했습니다.

### 단계 1. 기본 U-Net 학습과 데이터 증강

* **문제**: 가장 기본적인 U-Net 모델(입력 크기 $384 \times 384$)로 학습을 시작했더니 검증 점수가 `77.1307%`가 나왔습니다. 현미경 사진 특성상 시편이 놓인 방향이나 사진 밝기가 조금씩 달랐는데, 기본 모델은 이런 차이에 약했습니다.
* **시도**: 잘라낸 이미지 조각마다 4방향 회전($0^\circ, 90^\circ, 180^\circ, 270^\circ$)을 모두 적용하고, 밝기(감마)를 조금씩 바꿔가며 90 에폭 동안 충분히 학습시켰습니다. 다른 백본(ResNet34 등)이나 경계선에 가중치를 주는 손실 함수도 여러 가지 시도해 보았습니다.
* **확인**: 4방향 회전과 밝기 조절을 넣은 단일 U-Net이 **`78.9286%`**로 가장 잘 나왔습니다. 반면에 복잡하게 바꾼 일부 손실 함수나 백본 모델은 오히려 점수가 떨어졌기 때문에, 실제로 점수가 오른 설정만 남겼습니다.

### 단계 2. 역할을 나눈 6개 모델의 결과 합치기 (앙상블)

* **문제**: 모델 하나로 큰 덩어리(Primary Si, Al)와 아주 작은 입자(Eu)를 동시에 완벽히 찾기는 어려웠습니다. 특히 Eu 클래스의 점수가 `60%` 근처에서 잘 오르지 않았습니다.
* **시도**: 성질이 다른 모델들을 함께 써서 서로 부족한 부분을 보완하도록 구성했습니다.
  1. **YOLO11s 기반 분할 모델 (비중 50%)**: 전체적인 구조와 경계를 잘 잡는 주력 모델입니다. 작은 입자도 잘 보도록 작게 자른 영역을 확대한 이미지와 원래 크기 이미지를 섞어서 학습시켰습니다.
  2. **DINOv3 기반 분할 모델 (비중 25%)**: 넓은 문맥 특징과 원본 RGB 색상 정보를 함께 보는 모델을 추가했습니다.
  3. **성분별 전담 U-Net 4개 (비중 25%)**: 4개 성분을 한 번에 찾지 않고, 각 모델이 자기 담당 성분 하나만 맞히도록(이진 분류) 따로 학습시킨 뒤 4개 모델의 예측 확률을 합쳤습니다.
* **확인**: 한 모델이 헷갈리는 부분을 다른 모델이 잡아주면서 검증 점수가 **`80.0001%`**까지 올라갔습니다.

### 단계 3. 틀린 위치를 직접 확인하고 경계선 보정하기

* **문제**: 모델이 어디서 틀리는지 예측 마스크와 정답 마스크를 겹쳐서 확인해 보았습니다. 전체 틀린 픽셀의 `83.87%`가 성분과 성분이 맞닿는 **경계선 2픽셀 이내**에 몰려 있었고, 그중에서도 $\text{Al}_3\text{Ni}$와 Eu를 서로 반대로 예측한 오답이 약 `33.05%`를 차지했습니다.
* **시도**: 모든 사진에서 무조건 한쪽 성분을 넓히면 잘 맞힌 사진의 점수까지 깎였습니다. 그래서 **모델이 진짜로 헷갈려 하는 경계선 픽셀만 골라내는 조건**을 만들었습니다.
  * 예측된 경계선에서 2픽셀 이내이면서,
  * 가장 높은 확률 두 개가 $\text{Al}_3\text{Ni}$와 Eu이고,
  * 두 확률을 합치면 $0.6$ 이상인데 두 확률의 차이는 $0.2$ 이하로 박빙인 픽셀에서만,
  * 과하게 예측되던 Eu 확률을 살짝 낮추고 $\text{Al}_3\text{Ni}$ 쪽에 조금 더 힘을 실어주었습니다.
* **확인**: 추가 학습 없이 추론 단계에서 이 규칙만 적용해도 잘못 칠해진 Eu 픽셀이 줄어들며 전체 점수가 **`80.0070%`**(표시값 `0.8001`)로 소폭 올랐습니다.

### 단계 4. 가장 어려운 Eu 전담 모델의 입력 크기($640 \times 640$) 키우기

* **문제**: 제출용 코드를 정리하던 중 실수로 삭제된 Eu 전담 모델을 다시 학습시켜야 했습니다. 이때 기존처럼 $384 \times 384$ 크기로만 자르면 주변에 어떤 성분이 있는지 넓게 보지 못해 Eu를 구분하기 어렵다는 생각이 들었습니다.
* **시도**: 다른 5개 모델은 그대로 두고, Eu 전담 모델만 한 번에 보는 영역 크기를 $640 \times 640$(추론 이동 간격 $320$, 4방향 회전 예측 평균)으로 키워서 다시 학습시킨 뒤 전체 파이프라인에 연결했습니다.
* **확인**: 새로 뽑은 검증 20장 예측 마스크를 정답과 비교해 계산한 결과, 전체 검증 mIoU **`80.0503%`**를 달성했습니다.

### 추론 실행 예시 (Python)

CUDA가 지원되는 GPU 환경에서 6개 모델 가중치 폴더 경로와 예측할 이미지 폴더(또는 `.zip` 파일)를 지정하면 바로 예측 마스크를 생성합니다.

```python
from pathlib import Path
import komap_direct_infer as di

RUNS_ROOT = Path("/content/drive/MyDrive/KoMaP2026/runs")

# 1. 사용할 6개 모델 폴더와 가중치 파일 이름 지정

    "yolo": "Yolo모델",
    "dino": "Dino모델",
    "primary": "Primary_SI탐지",
    "ni": "Al3Ni탐지",
    "eu": "Eu탐지",
    "al": "Al탐지",

    "yolo": "best50.pt",
    "dino": "best.pt",
    "primary": "best.pt",
    "ni": "best.pt",
    "eu": "best.pt",
    "al": "best.pt",
}

RUN_PATHS = {role: RUNS_ROOT / name for role, name in RUN_NAMES.items()}

# 2. 추론 전 6개 모델 파일과 설정이 정상인지 먼저 확인
assets = di.inspect_assets(RUN_PATHS, checkpoint_names=CHECKPOINT_NAMES)

# 3. 새로운 이미지 폴더 또는 ZIP 파일 추론 실행 (이미지 장수 제한 없음)
result = di.predict_test(
    test_input=Path("/content/drive/MyDrive/KoMaP2026/data/test.zip"),
    output_dir=Path("/content/drive/MyDrive/KoMaP2026/outputs/result_01"),
    run_paths=RUN_PATHS,
    expected_count=None,
    checkpoint_names=CHECKPOINT_NAMES,
)

print("생성된 마스크 압축 파일:", result["masks_zip"])
```

## 6. 아쉬운 점과 배운 점

### 아쉬운 점 및 한계

1. **검증 데이터가 20장으로 적다는 점**: 평가용 테스트셋(10장)의 정답이 공개되지 않아 검증용 20장을 기준으로 모델을 고르고 경계선 보정값을 찾았습니다. 검증셋에서는 점수가 올랐지만, 데이터 수가 적은 만큼 완전히 새로운 사진에서도 똑같은 폭으로 점수가 오른다고 단정하기는 조심스럽습니다.
2. **변수를 하나씩만 완전히 통제하지 못한 점**: 최종 `80.0503%`가 나온 조합은 Eu 모델의 입력 크기를 $640 \times 640$으로 키워 다시 학습한 결과이지만, 재학습 과정과 실행 환경의 미세한 차이가 함께 반영된 결과이므로 패치 크기만의 효과라고 단정하지 않으려 합니다.

### 프로젝트를 통해 배운 점

* **직접 눈으로 오답을 확인하는 습관**: 더 크고 유명한 모델(DINO-L, HRNet-W48 등)로 바꿔보기도 했지만, 개별 모델 점수가 괜찮아 보여도 기존 모델들과 합쳤을 때 전체 점수가 오히려 떨어지는 경우가 많았습니다. 막연히 모델을 키우기보다, 실제로 어떤 픽셀에서 틀리는지 마스크를 비교해 보고 검증 수치로 확인하는 과정이 훨씬 중요하다는 것을 배웠습니다.
* **실행 가능한 코드로 마무리하는 경험**: 실험할 때만 돌아가는 코드와 다른 환경에서도 에러 없이 돌아가는 코드는 많이 다르다는 것을 느꼈습니다. 패키지 누락이나 경로 오류, 용량 문제를 직접 겪으며 사전 점검 기능과 깔끔한 추론 함수를 만들어 본 것이 가장 큰 수확이었습니다.
